# Custom GPTs vs. Agent Skills (SKILL.md): A Mid‑2026 Comparison

## TL;DR
- **Custom GPTs and Agent Skills solve overlapping problems with opposite architectures: a Custom GPT is a monolithic, ChatGPT-only configuration (instructions + knowledge + capabilities + one tool surface) you assemble in OpenAI's no-code builder; an Agent Skill is a portable, modular `SKILL.md` folder that any skills-compatible agent loads on demand via "progressive disclosure."** Use Custom GPTs to package a reusable assistant for ChatGPT users; use Agent Skills to package a reusable capability that travels across many agent products (per Anthropic PM Mahesh Murag in VentureBeat, Dec 18, 2025: "Microsoft has already adopted Agent Skills within VS Code and GitHub; so have popular coding agents like Cursor, Goose, Amp, OpenCode, and more").
- **The two are not mutually exclusive and increasingly converge:** ChatGPT "Apps" (formerly connectors) and Custom GPT "Actions" both now run on or alongside MCP, and OpenAI co-founded the Linux Foundation's Agentic AI Foundation (AAIF, announced Dec 9, 2025, co-founded by Anthropic, Block and OpenAI) and adopted the SKILL.md format in its Codex agent (developer Elias Judin found OpenAI used "the same file naming conventions, the same metadata format, the same directory organization"; Codex CLI reads skills from `~/.codex/skills`). A Custom GPT is the right tool for a no-code, text-in/text-out assistant distributed inside ChatGPT; an Agent Skill is the right tool for a version-controlled, cross-platform, code-executing capability.
- **Quality ceilings differ sharply.** An exemplary Custom GPT is a tightly-scoped, well-tested assistant under the ~8,000-character instruction limit with curated knowledge files; an exemplary Agent Skill is a lean (<500 line, <5k token) eval-driven `SKILL.md` whose description triggers reliably and whose bundled scripts/references load progressively. Agent Skills have a far more mature, documented evaluation and optimization methodology.

## Key Findings

### Part 1 — Custom GPT construction standard (mid-2026)
- **Builder surfaces:** The GPT Builder is still web-only (mobile can use but not build), with a conversational **Create** tab and a manual **Configure** tab. Configure fields are: Name, Description, Instructions, Conversation starters, **Recommended model** (a newer field), Knowledge (file upload), Capabilities, and either Apps or Actions. Version history (with restore) is accessible from the ••• menu; note that restoring an older version that uses actions may require reconfiguring authentication.
- **Models:** As of February 13, 2026, GPT-4o, GPT-4.1, GPT-4.1 mini, o4-mini, and the original GPT-5 (Instant and Thinking) were retired from ChatGPT; GPT-5.1 models were retired March 11, 2026. The mid-2026 lineup is the GPT-5 family: GPT-5.3 Instant (default for all tiers), GPT-5.4 Thinking / GPT-5.4 Pro (paid reasoning), with GPT-5.5 and GPT-5.5 Pro having rolled out April–May 2026 (GPT-5.5 Instant became the free-tier default May 5, 2026). Business/Enterprise/Edu kept GPT-4o inside Custom GPTs until April 3, 2026. Custom GPTs now support a "Recommended model" setting and users can switch models.
- **Knowledge limits:** Up to 20 files per GPT, each up to 512 MB. Most common document, spreadsheet, image, text, and code types are supported. Retrieval is RAG-based (semantic chunk retrieval); some file types require Code Interpreter & Data Analysis enabled. OpenAI does not publish its exact chunking/embedding parameters.
- **Capabilities toggles:** Web Search, Canvas, Image Generation, and Code Interpreter & Data Analysis. (Web Search, Canvas, and Image Generation default on; Code Interpreter defaults off.) Note: OpenAI announced canvas would no longer be available in GPT-5.5 Instant/Thinking, with writing/coding moving to in-chat writing/code blocks.
- **Actions vs Apps vs Connectors:** Actions = OpenAPI 3.0/3.1-schema API calls defined per-GPT, with API key or OAuth auth (Actions are not available in Pro mode). "Connectors" were renamed "Apps" on December 17, 2025; Apps are built on MCP. **A single Custom GPT can use either Apps or Actions, but not both at once** (an explicit OpenAI platform limitation). Custom MCP apps (developer mode) support read/write actions and require Business/Enterprise/Edu for full write capability; ChatGPT requires manual confirmation before any write action.
- **Instruction limit:** ~8,000 characters (hard limit in the builder field); overflow should be moved to knowledge files. (The underlying Assistants API allows far more — 256,000 chars — but the GPT Builder UI caps at 8,000.)
- **Sharing/publishing:** Three visibility options — Only me, Anyone with the link, GPT Store. Public GPT Store listing requires a verified Builder Profile (name or domain verification) plus policy compliance and human/automated review. Workspaces have private GPT sections with RBAC (Can chat / Can view settings / Can edit), ownership, and adoption analytics. A US-builder revenue program based on user engagement exists, though reported earnings are modest and the payout formula is undisclosed.
- **Evaluation:** OpenAI Academy recommends a lightweight eval approach: write 10–15 representative questions with correct answers, run them, and refine instructions/knowledge. Preview is the built-in test surface. Guidance favors tightening instructions and adding examples before adding more tools.
- **New since late 2025:** Apps/MCP support, version history with restore, the renaming of connectors to apps, a "Recommended model" field, and tighter integration with the broader ChatGPT agent/Projects ecosystem. (Note: Projects, not GPTs, get deep research, agent mode, and project-only memory; GPTs remain capped at 20 knowledge files and have no memory.)

### Part 2 — Agent Skills / SKILL.md
- **Definition:** Per agentskills.io, "Agent Skills are a lightweight, open format for extending AI agent capabilities with specialized knowledge and workflows. At its core, a skill is a folder containing a SKILL.md file." Originally developed by Anthropic, launched October 16, 2025, and "published... as an open standard for cross-platform portability" on December 18, 2025 (Anthropic engineering post).
- **SKILL.md format:** YAML frontmatter + Markdown body. Required frontmatter: `name` (1–64 chars, lowercase alphanumeric + hyphens, no leading/trailing/consecutive hyphens, must match the parent directory name) and `description` (1–1024 chars). Optional: `license`, `compatibility` (≤500 chars), `metadata` (arbitrary string key-value map), and `allowed-tools` (space-separated, experimental). The Markdown body holds instructions with no format restrictions.
- **Discovery/triggering — "progressive disclosure" in 3 stages:** (1) Discovery — only name+description (~100 tokens) loaded at startup for all skills; (2) Activation — the full SKILL.md body (<5,000 tokens / <500 lines recommended) loads when a task matches the description; (3) Execution — bundled scripts/references load only as needed. The `description` field is the primary trigger mechanism; best practice is to make it "pushy" and imperative ("Use this skill when...") to combat the known tendency to under-trigger.
- **Composition:** Skills are designed as "coherent units" that compose with each other and with tools — the "knowledge layer" on top of MCP tools. Skills work identically across Claude.ai, Claude Code, and the API; in Codex, skills are bundled into plugins alongside MCP servers and app connectors.
- **skill-creator tool:** A meta-skill with four modes — Create, Eval, Improve, Benchmark — backed by four composable subagents (Executor, Grader, Comparator, Analyzer) plus utility scripts for init, validation, eval prep, and benchmark aggregation with variance analysis.
- **Evaluation/benchmarking:** A rigorous, documented methodology: test cases in `evals/evals.json` (prompt + expected output + assertions), run with-skill vs without-skill (baseline), grade assertions PASS/FAIL with concrete evidence, aggregate to `benchmark.json` with mean/stddev pass rates and time/token deltas, blind A/B comparison via an LLM judge, and train/validation splits (~60/40) for description optimization to avoid overfitting.
- **Governance/versioning (primary-source verified):** Agent Skills remains **maintained by Anthropic** as an open standard, **not** a formal AAIF project — the Linux Foundation's AAIF founding projects are MCP, Block's goose, and OpenAI's AGENTS.md (Anthropic donated MCP, not Agent Skills, to the AAIF; agentskills.io is named separately as the spec home). The spec itself has **no formal version number** — github.com/agentskills/agentskills shows "No releases published"; it is a living document versioned by Git commits. Individual skills have **no required version field** — authors optionally place `version: "1.0"` inside the optional `metadata` map. License: repo code = Apache 2.0, docs = CC-BY-4.0; the example skills repo (anthropics/skills) is mixed (most Apache 2.0; the docx/pdf/pptx/xlsx document skills are source-available/proprietary). Validation uses the `skills-ref` Python reference library: `skills-ref validate ./my-skill`.
- **Distribution & enterprise:** Skills are distributed via Git/version control and bundled into "plugins" (a plugin = the distribution unit containing one or more skills + optional MCP servers, app mappings, hooks). Marketplaces index plugins: Claude Code's plugin system, OpenAI's Codex Plugin Directory (launched March 27, 2026, with enterprise JSON policy controls — INSTALLED_BY_DEFAULT / AVAILABLE / NOT_AVAILABLE), GitHub Copilot, and the JFrog Agent Skills Registry. Enterprise governance includes central admin provisioning (Anthropic Team/Enterprise), allow/deny lists, and version pinning — critical given documented supply-chain risk: Snyk's ToxicSkills audit (3,984 skills scanned as of Feb 5, 2026) found "13.4%...contain at least one critical-level security issue" and 36.82% have at least one security flaw, and Koi Security's "ClawHavoc" campaign flooded the ClawHub registry with hundreds of malicious skills in a multi-day window in late January 2026.

### Part 3 — Detailed comparison

| Dimension | Custom GPT | Agent Skill (SKILL.md) |
|---|---|---|
| **What it is** | A saved ChatGPT configuration (assistant) | A portable folder of instructions + resources |
| **Where it lives** | OpenAI's servers, inside ChatGPT | A filesystem/Git folder, loaded by any compatible agent |
| **Execution** | Runs inside ChatGPT's runtime | Runs inside the host agent's runtime (local code execution where supported) |
| **Composition model** | Monolithic — one bundle of instructions/knowledge/capabilities/one tool surface | Modular — many small skills compose; loaded on demand |
| **Trigger/routing** | User picks the GPT (or @-mentions it); always-on system prompt | Agent auto-selects via description match; progressive disclosure |
| **Knowledge integration** | Up to 20 files × 512 MB, RAG retrieval | `references/` files loaded on demand; no built-in vector store (relies on host) |
| **Tool/action integration** | Actions (OpenAPI) OR Apps (MCP) — not both | `scripts/` (executable code) + host's MCP tools + `allowed-tools` |
| **Testing/eval** | Informal (10–15 Q&A in Preview) | Rigorous eval harness (assertions, baselines, benchmarks, variance, blind A/B) |
| **Governance/versioning** | OpenAI-controlled; built-in version history + restore | Git-based; no required version field; Anthropic-stewarded open spec |
| **Portability** | Locked to ChatGPT | Cross-platform across 30+ agents |
| **Build skill required** | No-code | Markdown authoring; coding for scripts |
| **Quality ceiling** | Tight scope, <8k-char instructions, curated knowledge | Lean <500-line SKILL.md, eval-driven, reliable triggering |

**1. Architectural differences:** A Custom GPT is a persistent server-side assistant that exists only inside ChatGPT; you interact with it by selecting it. An Agent Skill is an inert folder of files that becomes active only when a host agent decides a task matches its description, then executes within that host's runtime (with local code execution where the host allows it). Custom GPTs centralize on OpenAI's infrastructure; Skills decentralize onto the filesystem/Git and travel with the user.

**2. Composition model:** Custom GPTs are monolithic — instructions, knowledge, capabilities, and a single tool surface (Apps OR Actions) are fused into one artifact, all loaded at conversation start. Skills are modular and additive — each skill is a small coherent unit, and many can coexist with a tiny context footprint because only names/descriptions load until activation. This makes Skills far more scalable for large capability libraries.

**3. Trigger/routing:** Custom GPTs are user-routed (a human chooses or @-mentions the GPT); the entire system prompt is always on. Skills are model-routed via description matching and progressive disclosure, which means routing quality depends heavily on description engineering (hence the dedicated optimization methodology and train/validation eval splits).

**4. Knowledge integration:** Custom GPTs provide first-class managed RAG (up to 20 files × 512 MB, automatic chunking/retrieval). Skills have no built-in vector store; they ground via `references/` files loaded on demand, deferring any RAG to the host environment. For document-heavy grounding with zero setup, Custom GPTs win; for procedural knowledge and lean reference loading, Skills win.

**5. Tool/action integration:** Custom GPTs connect via Actions (OpenAPI) or Apps (MCP) — but only one per GPT. Skills connect via bundled `scripts/` (directly executable code) plus whatever MCP tools the host exposes, with an experimental `allowed-tools` field. Skills are the "knowledge layer" that makes existing MCP integrations more usable.

**6. Testing/evaluation:** This is the starkest gap. OpenAI's official guidance is a lightweight 10–15 question check in Preview. Agent Skills ship a full eval discipline: assertion-graded test cases, with-skill-vs-baseline comparison, benchmark aggregation with mean/stddev and token/time deltas, blind A/B judging, and overfitting-aware description tuning — automated by skill-creator.

**7. Governance/maintenance:** Custom GPTs have OpenAI-managed version history with one-click restore but are entirely platform-controlled. Skills use Git-native versioning (commits, tags, plugin manifests) with no required version field; governance is enterprise-managed via admin provisioning, marketplaces, allow/deny lists, and version pinning. Drift detection in Skills is handled by re-running evals; Custom GPTs have no comparable harness.

**8. Portability:** Custom GPTs are fully locked to ChatGPT (OpenAI explicitly states GPTs are not a way to embed ChatGPT elsewhere — use the API for that). Skills are explicitly designed for "write once, use everywhere" across 30+ agent products under an open standard.

**9. Quality ceiling:** An exemplary Custom GPT is narrowly scoped, has prescriptive instructions well under 8,000 characters (community guidance: ~2,000 words), curated small knowledge files, only the capabilities it needs, and a deliberate Apps-or-Actions choice. An exemplary Skill is a lean (<500 line / <5k token) SKILL.md with a "pushy" imperative description that triggers reliably, progressive disclosure for detail, bundled tested scripts, and a passing eval suite that beats the no-skill baseline.

**10. When to use which:**
- **Custom GPT** when: your audience lives in ChatGPT; you want no-code; text-in/text-out is enough; you want GPT Store distribution or a workspace-internal assistant; you need managed RAG over documents.
- **Agent Skill** when: you need portability across tools; you want version-controlled, code-executing, composable capabilities; you need rigorous evaluation and drift detection; you work in coding/agentic environments (Claude Code, Codex, Copilot, Cursor).
- **Both** when: you maintain a canonical workflow as a Skill (portable, tested) and also expose a ChatGPT-facing Custom GPT for non-technical users; or build a ChatGPT App (MCP) that doubles as a cross-host capability.

## Recommendations
1. **Choose by audience and portability first.** If users are non-technical and inside ChatGPT, build a Custom GPT. If your capability must run in coding agents or across vendors, write an Agent Skill. Threshold to revisit: if you find yourself rebuilding the same GPT logic for Claude/Codex/Cursor, migrate the core to a Skill and keep the GPT as a thin ChatGPT-facing wrapper.
2. **For Custom GPTs:** keep instructions under ~2,000 words (well within the 8k-char hard limit), move bulk reference into knowledge files (never duplicate content between Instructions and Knowledge), enable only needed capabilities, choose Apps OR Actions deliberately (you cannot have both), test in Preview with a 10–15 question eval set, and verify your Builder Profile before GPT Store publishing. If you need deep research, agent mode, or memory, consider a Project instead of (or alongside) a GPT.
3. **For Agent Skills:** keep SKILL.md <500 lines / <5k tokens, write a "pushy" imperative description and optimize it with a train/validation query split, use progressive disclosure (`references/`, `scripts/`, `assets/`), and run the skill-creator eval loop (with-skill vs baseline, assertion grading, benchmark/variance) before distribution. Package proven skills as plugins, pin versions, and install only from trusted/vetted marketplaces given the documented prevalence of malicious skills.
4. **Hedge against lock-in:** author canonical workflows as Skills (portable, version-controlled, testable) and wrap a thin Custom GPT for ChatGPT reach. Because both ecosystems are converging on MCP, investing in a clean MCP tool layer pays off in both paradigms.
5. **Benchmarks that change the call:** Move from Custom GPT to Skill once (a) you have ≥2 target agent platforms, (b) you need objective pass/fail QA, or (c) drift after model updates is causing silent regressions. Stay on Custom GPT if your only surface is ChatGPT and your workflow is text-only with no code execution needs.

## Caveats
- OpenAI does not publish exact knowledge chunking/embedding parameters for Custom GPTs; RAG behavior is inferred from documentation and general industry practice.
- The ChatGPT model lineup is changing rapidly (GPT-5.5 rolled out April–May 2026); the exact default model, canvas availability, and Custom GPT model options may shift again after this writing.
- Third-party blogs incorrectly claim Agent Skills governance "moved to the AAIF"; primary sources confirm it remains an Anthropic-stewarded open standard and is NOT among the AAIF's founding projects (MCP, goose, AGENTS.md).
- Some "Custom GPT Actions deprecated" claims in 2026 blogs are inaccurate — Actions remain documented and supported in the OpenAI Help Center as of mid-2026 (one community report notes a mobile-client regression in invoking Actions, which is a bug, not a deprecation).
- GPT Store revenue figures from secondary sources are anecdotal/marketing-driven; OpenAI has not disclosed the payout formula or total pool.
- Skill-marketplace security statistics (Snyk ToxicSkills, Koi Security ClawHavoc) come from vendor audits; exact counts vary with registry growth and scan dates.
