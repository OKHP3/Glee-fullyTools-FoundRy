## Execution and ownership

Use the [collaboration protocol](../../agent-collaboration.md). The [assignment register](assignments.json) contains 20 FoundRy and six website packets, exact owned paths, requested model/effort, acceptance and dispatch status. Each worker gets its own Codex project worktree and named branch, reads the current repository guide and commits only its assigned outputs. Requested model settings are dispatch configuration; measured usage and actual savings remain unknown.

All first-wave outputs are independent additions. Existing app/server.py, app/static/, canon, governance, existing website HTML/CSS/JS, generated files and CI are read-only to workers. Replit's unpublished scope remains unknown; this program reserves all existing shared runtime files and Replit checkout operations. A worker finding an existing output path or an overlapping assignment stops that mutation and reports the collision. No unique Replit work is discarded or presumed synchronized.

Website PRs #31 and #32 were open at planning time. Their release, workflow, generated-artifact, shared documentation and maintenance scopes are excluded. Workers recheck current origin/main and open PRs before editing. Existing September 5 website corrective-program outcomes must not be rediscovered as new work.

Workers may read current source, create their assigned new files and commit on their own branch. They do not push, create 26 PRs, merge, deploy, change billing, install dependencies or spawn further agents. The coordinator reviews commits and groups accepted independent outputs into one PR per repository when ready. A defect outside assigned files gets a reproduction and proposed fix location, then a separately assigned serialized repair. A failing regression does not get weakened or merged as a green gate.

## Cost and constructive competition

Use GPT-5.4 mini at low effort for narrow tests, examples and documentation, and GPT-5.6 Luna at medium effort for concurrency, browser behavior and data-contract reasoning. This is a capability-based allocation, not a verified price comparison. Avoid broad history ingestion, repeated research, unchanged polling and duplicate full-suite execution. Reuse installed browser tools; absence is NOT RUN, not permission to install. No paid external model calls.

Compare contributions by useful accepted outcome, evidence quality, scope discipline and owner rework. All four matter more than speed or number of files. Record actual tokens/cost only if exposed. No invented savings, rankings, maturity scores or observed pilot passes. Workers can challenge assumptions with evidence; do not commission competing implementations of the same change. Share reusable findings through compact handoffs.

## Acceptance and integration

1. Worker reports base/head SHA, branch, owned paths, checks/results, exact defects, limitations and next action.
2. Coordinator checks task value, scope, conflicting assumptions and negative-test quality; accepts, requests a bounded correction or records no justified change.
3. Reconcile F15/F16/F17 proposals together before adopting any schema/runtime design. Pilot examples remain synthetic with observations not-run. Browser findings do not imply accessibility certification.
4. Run integration checks once per relevant source revision. Preserve owner data and source authority. Required CI and normal repository review remain gates.
5. Verify merge, receiving-host parity and cleanup independently. Branches/worktrees with unreviewed commits remain preserved. This register records dispatch, not completed implementation or Replit receipt.
