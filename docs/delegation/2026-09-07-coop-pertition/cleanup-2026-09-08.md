## Preservation failure and recovery boundary

The coordinator archived task threads before finishing worktree-file backups.
Codex removed most associated worktrees during that operation. Two artifacts
previously inventoried were then unavailable:

- F14: ignored `.foundry-data/foundry.sqlite3` in the worker checkout.
- W03: a modified generated `assets/audit/validation-report-2026-05-03.json`.

Their exact bytes have not been recovered. Git bundles preserve committed
content, not these uncommitted or ignored files. The F14 transcript records
imports of synthetic Temporary Intake Fixture and Incident Intake Log projects;
this establishes observed test activity, not an exact inventory of the lost
SQLite database or permission to discard it. The committed pilot source and
W03 prototype remain on main. The owner-main database was not removed or edited
by this cleanup.

F14 and W03 archived transcripts were copied into the private recovery archive.
A bounded search found no surviving exact worktree paths, matching deleted-open
file handles or local Time Machine snapshots. Trash enumeration was denied by
macOS privacy controls; it was not bypassed. No byte-for-byte recovery is claimed.
Regenerating a report or reimporting a fixture would be reconstruction, not recovery.

The earlier integration review's statement that W03's audit mutation was
preserved describes its pre-cleanup state and is superseded by this exception.
Future cleanup must back up and verify all working data before archiving a thread,
since thread archiving can also remove its worktree.
